@AGENTS.md

## Tooling

- **pnpm only.** Use `pnpm install`, `pnpm dev`, `pnpm <script>` and `pnpm dlx`; never npm or npx, and don't create `package-lock.json`. The version is pinned in `package.json` (`packageManager`), and CI and Netlify use it.
- **Restart cache gotcha:** Turbopack caches dev compiles in `.next/dev/cache`, and it can miss changes to CSS files that `globals.css` `@import`s (the generated palette and type scale). If `pnpm dev` shows a stale CSS error for code that no longer exists, run `rm -rf .next` and restart.

## Forms and analytics

- **Contact form uses Netlify Forms.** On Netlify's Next runtime, pages aren't static HTML, so Netlify detects forms from `public/__forms.html` and `ContactForm` posts urlencoded data there (with a no-JS fallback that redirects to `/contact/thanks`). Field names in `__forms.html` MUST match `src/components/contact-form.tsx`. It has a honeypot (`bot-field`). Locally the POST has nowhere to go, so tests mock it. Not yet verified on a real deploy.
- **Analytics** (`src/components/analytics.tsx`) renders only when `CLOUDFLARE_ANALYTICS_TOKEN` is set. It's cookieless. To change provider, replace that one component.

## Styling conventions

- **Semantic classes in markup, utilities in CSS.** JSX uses named classes (`.artist-card`, `.stack`, `.button--secondary`). Tailwind utilities are applied inside those classes with `@apply`. Avoid inline utility classes in JSX; reach for one only when no semantic class fits, and then prefer adding a semantic class.
- **Where styles live** (all imported by `src/app/globals.css`, inside `@layer components`):
  - `src/styles/typography.css`: `.display`, `.heading-1..4` (also the default for `h1..h4`), `.lead`, `.small`, `.caption`, `.eyebrow`, `.muted`, `.link`, `.measure`.
  - `src/styles/layout.css`: `.page`, `.stack` (`--sm|--lg|--xl`), `.cluster`, `.section-header`, `.image-cover`, `.image-contain`.
  - `src/styles/components.css`: one BEM-style block per component (`.block`, `.block__element`, `.block--modifier`).
  - `src/styles/styleguide.css`: `/styleguide` only.
- **Naming:** `block__element` for parts, `block--modifier` for variants. Use `[aria-current]`, `[aria-expanded]` and other state attributes in selectors rather than conditional class names.
- **Type scale is generated.** Edit the config in `scripts/type-scale.mjs`, run `pnpm type-scale`, and never hand-edit `src/styles/type-scale.css` or `type-scale.generated.json`. Sizes are fluid `--text-*` tokens (`text-xs` to `text-6xl`) that replace Tailwind's defaults.
- **Color is primitives mapped to semantic roles.** Primitive ramps named by color (`paper`, `ink`, `gold`, `red`, `green`, `navy`) are generated by `scripts/color-ramps.mjs` into `src/styles/palette.css` (brand values pinned to exact steps, the rest interpolated in OKLCH). Keep ramps smooth: pin as few steps as possible, each at the step whose lightness is closest to its own (a light gold sits near 300, not 500); Steps 50 and 100 are generated as a soft tint (unless pinned) so a ramp opens gently; `pnpm color-ramps` warns when a ramp's lightness steps are uneven. Run `pnpm color-ramps` after editing the pins, and never hand-edit `palette.css` or `palette.generated.json`. **Roles are hand-edited** in `src/styles/roles.css`: each points at a ramp step (or a plain hex), for light and for dark, and changes show up live with no build step. `pnpm check:contrast` measures every pairing against WCAG for light and dark; it only reports (CI and `pnpm test` run it), it never blocks dev or the build. The model: each primitive has one job in both modes and dark mode uses the other end of the ramp (`paper` = backgrounds, surfaces, dividers, hover fills; `ink` = text and strokes; `gold` = accent fills; `red` = highlight and error; `navy` = focus), so never point a role at a ramp outside its job. Never write a hex value, a color name (`gold`, `red`) or a ramp step (`ink-700`) in components or other CSS; use roles. Roles: `background`, `surface`, `surface-raised`, `surface-sunken`, `foreground`, `muted`, `subtle`, `scrim`, `outline`, `border`, `line`, `hover`, `accent`, `accent-foreground`, `accent-hover`, `accent-edge`, `accent-text`, `accent-soft`, `highlight`, `highlight-foreground`, `highlight-text`, `error`, `error-text`, `error-soft`, `focus`. Guidance is at the top of `roles.css`: the surfaces form a ladder (`surface-sunken` for bands and the footer, `background`, `surface` for cards and inputs, `surface-raised` for the nav pill and menus), so don't overload `surface`; `subtle` is a third text tier; `scrim` is the base color for a translucent fill behind text on a photo (opacity applied where used); `border` is for container edges, between `line` and `outline`. `accent` (gold) for fills such as buttons, `highlight` (red) for underlines and state marks (3:1), `error` (3:1) for invalid borders and alert edges, `error-text` for error messages, `error-soft` for the alert tint, `outline` (3:1) for borders on interactive controls, `line` for decorative dividers. Native checkbox and radio fills come from `accent-color: var(--foreground)` on `:root` (globals.css), not the gold `accent`: gold is 1.9:1 on paper, under the 3:1 a state indicator needs, and unset browsers draw blue. A separate component-token layer (`--field-*`, `--button-*`) is deliberately not used yet: add one only when a component needs a value that differs from its role in one theme, or two components share a value that may diverge. Buttons are gold by default (`.button`) with an `accent-edge` border (gold-500 in light: the gold fill alone is 1.9:1 on paper, and the deeper edge gives the shape 3:1; in dark it equals the fill); `.button--ink` is the solid-dark alternative and resets that border, as do the ghost and secondary variants. `src/styles/theme.css` maps roles to Tailwind utilities.
- **Fonts:** Cosmic (`font-display`) is for headings and display type, and Hanken Grotesk (`font-sans`) for everything else.
- **Spacing is a fluid scale too.** `pnpm type-scale` also writes `--spacing-fluid-3xs` to `--spacing-fluid-3xl`, used as `gap-fluid-md`, `p-fluid-lg`, `py-fluid-xl`. Prefer these over numeric utilities (`gap-4`) for layout spacing. The `fluid-` prefix is load-bearing: a bare `--spacing-md` would hijack Tailwind's `max-w-md`, `w-xl` and other size utilities that share the same names.
- **Figma is a mirror, not a source.** After changing a role, a ramp pin, the type scale, a motion token or a layout value (max widths, radii, the 44px target), run `pnpm figma-manifest`. It writes `figma/manifest.json` with a hash, and the Figma file's Sync page records the hash it matches. Never hand-edit the manifest. If the hash differs, the mirror is stale: re-sync Figma from the manifest. Layout values that live in Tailwind utilities are named in `scripts/figma-manifest.mjs`; add one there when a component gets a new shared measurement. Fonts and weights are there too: both fonts are variable (100 to 900), so Figma text styles bind numeric weight variables (`font/weight/thin` to `black`, the nine Tailwind steps, regular is `font-normal`), never style names ("Semi Bold" vs "SemiBold"). Any weight class works in code without a manifest change; only 400, 500 and 600 are used today.
- **New UI goes in `/styleguide` first**, then into components.

## Accessibility conventions

- **Landmarks and skip link** live in `SiteShell` (`skip-link`, `<main id="main" tabindex="-1">`). Don't remove or reorder them; the skip link must stay the first tab stop.
- **Touch targets:** standalone interactive elements are at least 44px (`min-h-11`). Inline links inside running text are exempt. Only use `.button--sm` for compact, secondary controls.
- **State is never color alone.** Current page or section uses `aria-current` with an underline (nav) or fill plus weight (filter chips). Style from the attribute, not a class.
- **Form fields and errors:** build fields with `Field` (`src/components/ui/field.tsx`), which wires the label, hint and error and sets `aria-invalid` and `aria-describedby` (error first). An invalid control gets a red border plus an inset ring (a box-shadow, so nothing shifts; focus still uses `outline`) and a text message in `error-text`, so it is never color alone. The contact form validates inline: it sets `noValidate` only after scripts run (natively validated before that and without JavaScript), focuses the first invalid field, announces the count once, and clears a field's error as it is fixed. Messages live in the `messages` table in `contact-form.tsx`.
- **Motion:** use `--duration-fast|base|slow` and `--ease-out`. A global `prefers-reduced-motion` rule in `globals.css` shortens all transitions and animations, so don't add animation that depends on running for its meaning.
- **Forced colors:** buttons keep a transparent border so they keep an edge when fills are removed. Focus uses `outline` (never box-shadow) with the `--focus` role.
- **Images:** content images get descriptive `alt`. Use `alt=""` when the same link already has the name as text (artist cards).
- **Heading order:** don't skip levels. Components that render headings take a `headingLevel` (see `ArtistCard`).
- **404 and error titles:** render `<title>` inside the component (`NotFoundContent`, `ErrorContent`). The `metadata` title on a not-found page is replaced by the layout default after hydration.
- **Known framework quirk:** Next serves `notFound()` responses with `<html id="__next_error__">` and no `lang` until hydration. Everything is correct after hydration, and the 404 status and content are right.
- **`pnpm test` guards all of this.** It seeds fixture content, builds, and runs Playwright: axe-core (WCAG 2.0 to 2.2 A/AA plus best-practice) on every route in light and dark at phone and desktop widths, plus interaction tests (skip link, nav state, piece viewer, 404, contact form, reduced motion, 44px targets). CI runs it. When you add a route, add it to `tests/routes.ts`; when you add standalone controls, the touch-target test covers them.
- **Editable pages:** Aftercare (`content/aftercare.mdoc`) and FAQ (`content/faq/*.mdoc`) are Keystatic Markdoc rich text (`richText` in `keystatic.config.ts` limits what an editor can make), read with `getAftercare()` and `getFaqs()` and rendered by `RichText` (`.richtext` in typography.css). Each page supplies its own h1, so editor headings start at h2. Empty pages show a message pointing to `/contact`.
- **Test fixtures:** `scripts/fixtures.mjs` writes `zz-fixture-*` content and removes only those paths afterwards. Never name real content `zz-fixture-*`. Aftercare is one fixed file, so its fixture is written only if `content/aftercare.mdoc` doesn't exist and removed only while it still equals the fixture text; the Aftercare test skips when real content is present. `pnpm test` leaves `.next` built with fixture content, so run `pnpm build` before `pnpm start` for real output.
- **Formatting:** `pnpm format` (Prettier with the Tailwind plugin). CI runs `format:check`.
