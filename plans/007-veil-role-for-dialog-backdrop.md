## Why this matters

The project rule is that components use color roles only, never a hex, a color
name or a ramp step. One place breaks it: the piece-viewer dialog's backdrop is
`backdrop:bg-black/80` in `src/styles/components.css:199`. The existing `scrim`
role cannot replace it, because `scrim` is the paper wash (light in light mode) meant
for text over a photo, and a light veil behind a dialog would not dim the page. A
dedicated role that is dark in both themes fixes the rule violation and gives the
owner a knob (and a Figma variable) for the veil.

## Current state

`src/styles/components.css:199` (the piece dialog):

```css
@apply m-auto max-h-[92dvh] w-[min(64rem,calc(100vw-1.5rem))] overflow-auto overscroll-contain bg-background text-foreground backdrop:bg-black/80;
```

`src/styles/roles.css`: `--scrim` sits in the light block (line 60,
`--scrim: var(--paper-50);`) and again in the dark block (line 90,
`--scrim: var(--paper-950);`). The header comment documents each role (the `scrim`
entry reads `scrim ................ base color for a translucent fill behind text on a`
`photo (apply the opacity where it is used)`).

`src/styles/theme.css` maps every role to a Tailwind color, for example:

```css
--color-scrim: var(--scrim);
--color-outline: var(--outline);
```

Opacity modifiers already work on role colors in this repo, for example
`hover:bg-foreground/85` at `components.css:87`.

`src/app/(site)/styleguide/page.tsx` has a `roles` array (lines 18-44) that drives
the Color swatches, for example `{ name: "scrim", note: "fill behind text on photos" },`.

Role jobs (from `roles.css` header): `paper` = backgrounds, surfaces, dividers;
`ink` = text and strokes; "never point a role at a ramp outside its job (no ink
backgrounds)". So the veil points at the darkest paper step, which is a
background color in both themes.

## Steps

### Step 1: Add the role

In `src/styles/roles.css`:

- Add to the light block, after `--scrim: var(--paper-50);`:
  `--veil: var(--paper-950);`
- Do NOT add it to the dark block: `paper-950` is already right in dark, and the
  dark block lists only what differs from light.
- Add a guidance line in the header comment, after the `scrim` entry, in the same
  format: `veil ................. base color for the page-dimming layer behind a modal
dialog (dark in both themes; apply the opacity where it is used)`.

**Verify**: `grep -n "veil" src/styles/roles.css` shows the variable once and the comment.

### Step 2: Map it to Tailwind and list it in the styleguide

- `src/styles/theme.css`: add `--color-veil: var(--veil);` after `--color-scrim: var(--scrim);`.
- `src/app/(site)/styleguide/page.tsx`: add
  `{ name: "veil", note: "dims the page behind dialogs" },` to the `roles` array
  right after the `scrim` entry.

**Verify**: `grep -n "veil" src/styles/theme.css "src/app/(site)/styleguide/page.tsx"`
shows one line in each file.

### Step 3: Use it

In `src/styles/components.css:199` replace `backdrop:bg-black/80` with
`backdrop:bg-veil/80`. Change nothing else on that line.

**Verify**: `grep -rn "bg-black\|text-white\|bg-white" src` prints nothing.

### Step 4: Manifest, checks, full test

Run `pnpm figma-manifest`, `pnpm check:contrast`, `pnpm format:check`,
`pnpm lint`, `pnpm test`.

**Verify**: all exit 0. Note the new manifest hash; the owner must re-sync Figma
to get the new `veil` variable (do not use any Figma tool yourself).

## Maintenance notes

- In dark mode the dialog surface (`bg-background`, paper-950) and the veil
  (paper-950 at 80%) are nearly the same color, so the dialog edge relies on the
  photo and content. If the owner wants a defined edge, add a `border` or
  raised surface to the dialog in a separate change.
- If the owner retunes `paper-950`, the veil follows.
- A `veil` value that is not in the palette (a hex) would break the roles-only
  rule; keep it pointing at a paper step.
